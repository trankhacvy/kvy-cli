# P4-4.1-git-diff-panel — Git diff panel: daemon git.status/git.diff RPCs, web diff viewer, workspace base-ref config

**Section:** Phase 4 §4.1 Git panel (plan.md §16; falcon-prd.md FR-7.7; design §4.4)

First Phase 4 task — no blocking dependency, as scoped. All three §4.1 bullets
are implemented. This is new code (N), not a Happy port: Happy's mobile app
has no git diff panel, so there was nothing to port faithfully from — the RPC
shapes were already sketched in `@falcon/wire`'s `rpc.ts` (forward-declared,
unregistered) and this task fills in the daemon handlers, the CLI command,
and the web UI around them.

## What was built

### 1. Daemon `git.status`/`git.diff` RPCs

- **`packages/wire/src/rpc.ts`** — `GitStatusParamsSchema`/`GitStatusResultSchema`
  and `GitDiffParamsSchema`/`GitDiffResultSchema` already existed (forward-declared
  by an earlier task) but had no exported `z.infer` type aliases; added
  `GitStatusParams`/`GitStatusResult`/`GitDiffParams`/`GitDiffResult`/`FsReadParams`/
  `FsReadResult` (the last two were the same gap on `fs.read`, fixed for
  consistency even though `fs.read` itself is still a later bullet). Added one
  new field, `GitDiffResultSchema.truncated: z.boolean()` (additive-only,
  matches `FsReadResultSchema`'s existing `{inline, blobRef, truncated}` shape) —
  see the "blobRef" note below for why. Regenerated
  `src/__tests__/__fixtures__/wire-shapes.json` via `scripts/snapshot-shapes.ts`
  so the additive-only lint's frozen baseline picks up the new field (the
  schemas themselves were already registered in `schemaRegistry.ts`).
- **`packages/cli/src/daemon/gitExec.ts`** (new) — shared `execFile`-wrapped
  `git <args>` runner (`GitExec` type, `GitExecError`), same hand-wrapped
  shape as `gitWorktree.ts`'s own private `runGit` (kept as a separate copy
  rather than importing it — that module exports nothing, and status/diff
  reads have no reason to couple to the worktree-creation module).
- **`packages/cli/src/daemon/gitStatus.ts`** (new) — `getGitStatus({worktree})`
  runs `git status --porcelain=v2 --branch` and parses branch/ahead/behind
  (from the `# branch.head`/`# branch.ab` header lines) plus every changed-file
  record type porcelain v2 emits (ordinary `1 XY ...`, renamed/copied `2 XY ...`,
  unmerged `u XY ...`, untracked `? ...`) into `FileStatus[]`. No upstream ⇒
  ahead/behind default to 0 (no `branch.ab` line to parse) rather than erroring.
  Propagates a real `git` failure (not a repo, etc.) as `GitExecError` — no
  silent empty-status fallback.
- **`packages/cli/src/daemon/gitDiff.ts`** (new) — `getGitDiff({worktree, path?, baseRef?})`
  resolves the effective base ref as: explicit `params.baseRef` → the
  workspace's configured base ref (`workspaceConfig.ts`, injectable as
  `resolveConfiguredBaseRef`) → `HEAD` (uncommitted changes only, when nothing
  is configured). Runs `git diff <ref>` — **two-dot**, not three-dot
  `<ref>...HEAD` — deliberately: it diffs the working tree directly against
  `<ref>`'s tree, so the result includes both the branch's committed changes
  *and* any in-progress uncommitted edits, which is what a live agent
  session's "everything changed so far" panel needs. Optionally scoped to one
  `path` via `-- <path>`.
  - **`blobRef`/truncation:** the task brief calls for "a blobRef path for
    large diffs," but Phase 4.3's blob-storage subsystem (presigned upload/
    download routes + S3/local-disk drivers) doesn't exist anywhere in this
    codebase yet — same situation `adopt.mirror`'s own `blobRef` field was
    already in before this task (design §4.4: "unset until that subsystem
    lands"). Followed that exact precedent rather than building a blob
    subsystem out-of-scope for this task: a diff over ~60KB is truncated
    inline at the last full line boundary with `truncated: true` and an
    explicit "(diff truncated at N bytes)" marker, `blobRef` stays reserved
    and unset. `fs.read`'s wire schema already had this identical
    `{inline, blobRef, truncated}` shape for the same reason — `GitDiffResultSchema`
    just needed the same `truncated` field added (see above).
- **`packages/cli/src/daemon/machineRpc.ts`** — registered `"git.status"`/
  `"git.diff"` in `MACHINE_RPC_METHODS`, added injectable `getGitStatus`/
  `getGitDiff` deps (defaulting to the two modules above), wired into the
  method dispatch table. No idempotency-key caching (like `fs.list`/`fs.mkdir`,
  unlike `spawn`/`adopt.*`) — both are pure reads with no side effect a retry
  could double up.

### 2. `falcon workspace config --base-ref/--remote` command

- **`packages/cli/src/persistence.ts`** — added `Settings.workspaces?: Record<string, {baseRef?, remote?}>`
  (additive field, normalized the same field-by-field way every other
  `Settings` field is), reusing the existing atomic lock-file-guarded
  `settings.json` read-modify-write rather than a second file with its own
  locking scheme.
- **`packages/cli/src/workspaceConfig.ts`** (new) — `readWorkspaceGitConfig`/
  `setWorkspaceGitConfig`, keyed by the workspace directory's **real**
  (symlink-resolved) absolute path (`resolveWorkspaceKey`, falls back to the
  plain resolved path if the directory doesn't exist yet) — this is the same
  store `daemon/gitDiff.ts` reads by default, so a `git.diff` RPC call
  omitting `baseRef` picks up whatever `falcon workspace config` set.
- **`packages/cli/src/commands/workspaceConfig.ts`** (new) — `runWorkspaceConfigCommand`:
  with `--base-ref`/`--remote`, merges the patch and prints the result; with
  neither, just reads and prints the current config (no write). `--directory`
  defaults to `process.cwd()`.
- **`packages/cli/src/index.ts`** — the `workspace-config` command type (arg
  parsing already existed, `args.ts` already had `parseWorkspaceConfig` wired
  from an earlier task) was a `"not implemented yet"` stub; replaced with a
  real `runWorkspaceConfig` that calls the command above. Deliberately does
  **not** call `ensureDaemon()` — this command only touches `settings.json`
  directly, same rationale as `doctor` skipping the daemon-auto-start step.

### 3. Web: changed-files list + unified diff viewer

- **`packages/web/src/sync/machineRpc.ts`** — added `"git.status"`/`"git.diff"`
  to the caller-side `MachineRpcClient`'s method table (params/results/result
  schemas), mirroring the CLI-side registration.
- **`packages/web/src/lib/unifiedDiff.ts`** (new) — parses `git diff`'s
  unified-diff text into `{files: [{path, oldPath, newPath, binary, hunks: [{header, lines}]}]}`,
  tracking old/new line numbers per hunk. Handles multi-file diffs, added/
  deleted files (`/dev/null` sides), binary-file markers, and the
  `\ No newline at end of file` marker line. 9 tests.
- **`packages/web/src/lib/diffHighlight.ts`** (new) — shiki-based per-line
  tokenization (`codeToTokens`, `theme: "github-dark"`, same theme
  `markdown.ts` already uses), one call per file (not per line, so multi-line
  grammar constructs stay correct and highlighting is fast), with a
  `languageForPath` extension→shiki-language map and a plain-text fallback on
  any tokenization failure — highlighting is cosmetic, so it must never hide
  diff content. Returns raw `ThemedToken[][]`, not pre-rendered HTML/React —
  the viewer component turns each token into a real `<span>`, never
  `dangerouslySetInnerHTML` (same rule `markdown.ts` documents). 7 tests,
  running real shiki (no mocking), same pattern as `markdown.test.ts`.
- **`packages/web/src/features/git-diff/`** (new feature area, mirrors
  `features/new-session`'s injectable-actions/mock-source/live-actions
  structure):
  - `types.ts` — `GitDiffActions` (`fetchStatus`/`fetchDiff`), `UseGitDiffActions`.
  - `live-actions.ts` — `machineRpcToGitDiffActions`, adapts a `MachineRpcClient`.
  - `mock-source.ts` — `useMockGitDiffActions`/`createMockGitDiffActions`,
    a fixed changed-files set with real parseable mock diffs (used as the
    default data source, since no screen has a live `apiSocket` + per-machine
    crypto client wired in yet — same state every other feature area in this
    codebase is currently in).
  - `use-git-panel.ts` — `useGitPanel`, two `@tanstack/react-query` queries
    (`git.status` once per worktree; `git.diff` re-fetched on file selection,
    `enabled` gated on status having loaded first).
  - `components/FileStatusBadge.tsx`, `ChangedFilesList.tsx`,
    `UnifiedDiffViewer.tsx`, `GitDiffPanel.tsx` — the actual UI. `GitDiffPanel`
    takes an injectable `useActions` prop (defaults to the mock), same seam
    shape as `NewSessionScreen`.
  - `index.ts` — barrel export.
  - 8 tests across `__tests__/live-actions.test.ts` and `__tests__/mock-source.test.ts`
    (`.tsx` components aren't unit tested — this package's vitest config only
    collects `src/**/*.test.ts` in a `node` environment, same constraint
    `directory-step-logic.ts`'s own doc comment calls out).
- **`packages/web/src/app/session/[id]/git/page.tsx`** (new route) — mounts
  `GitDiffPanel`, static-exported with `generateStaticParams` returning the
  `demo` id (same pattern as `/session/[id]/page.tsx`).
- **`packages/web/src/components/timeline/SessionTimelineScreen.tsx`** — added
  a "Files changed" link in the session header to the new route, so the panel
  is actually reachable from the existing timeline screen rather than only
  living at a URL nobody links to.

## Assumptions / deltas

- **Base-ref resolution fallback to `HEAD`:** the design only specifies
  `baseRef` as an optional RPC param plus a per-workspace config; it doesn't
  say what happens with neither. Chose `git diff HEAD` (uncommitted changes
  only) as the no-config default — a repo with nothing configured still gets
  a useful diff instead of an RPC error.
- **`truncated` field added to `GitDiffResultSchema`:** additive, mirrors
  `FsReadResultSchema`'s existing identical field for the same "no blob
  subsystem yet" situation. Regenerated the wire-shapes fixture accordingly.
- **No idempotency-key caching for `git.status`/`git.diff`:** both are pure
  reads (unlike `spawn`/`adopt.take`/`adopt.mirror`'s side-effecting or
  mid-write-sensitive operations) — a retry just re-reads current repo state,
  so caching would only serve stale results. `idempotencyKey` is still
  required on the wire params for uniformity with the rest of this RPC
  family; it's simply unused by these two handlers (same as `fs.list`/
  `fs.mkdir`'s existing precedent).
- **`workspaceConfig.ts` keys by real (symlink-resolved) path**, falling back
  to the plain resolved path when the directory doesn't exist — so
  `falcon workspace config` can pre-configure a workspace before it's ever
  been diffed, and a lookup miss on the daemon side just means "no config
  set" rather than a crash.
- **Web Git panel is a standalone feature area with mock data**, same
  not-yet-wired-to-a-live-`apiSocket` state as every other `features/*`
  screen in this codebase (`session-list`, `new-session`, `session-control`).
  Wiring the real per-machine crypto client + `apiSocket` in is out of scope
  here (it's out of scope for every other feature area too, pending the sync
  engine's machine-level wiring).
- **Two-dot `git diff <baseRef>`, not three-dot:** deliberate — see the
  "Daemon git.status/git.diff RPCs" section above for the rationale
  (uncommitted changes must be included).

## What was not built (explicitly out of scope)

- Real blob-storage-backed large diffs (`blobRef` stays reserved/unset —
  Phase 4.3 work).
- Wiring the web Git panel to a live `apiSocket` + per-machine crypto client
  (blocked on the same sync-engine machine-level wiring every other feature
  area is waiting on).
- Commit/push/"create PR" actions (falcon-prd.md FR-7.7 explicitly scopes
  these to a `[P2]` fast-follow; MVP is read-only).
- `fs.read` machine RPC (a separate, later wire-schema entry this task
  touched only incidentally, to add its missing type export for
  consistency — no handler for it was implemented).
