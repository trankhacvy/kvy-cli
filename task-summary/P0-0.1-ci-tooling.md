# P0-0.1-ci-tooling — Root linting (Biome) and CI workflow

**Section:** Phase 0 — Repo & contracts (M0) / plan.md §16 "0.1 Scaffold", bullet 2:
"Biome (or ESLint+Prettier — pick one) at root; CI workflow: install → build wire →
typecheck → test on PR"

## What was done

This worktree was branched from `P0-0.1-monorepo-scaffold` (not `main`) because the
task explicitly builds directly on that task's `package.json` / `turbo.json` /
`pnpm-workspace.yaml`, which aren't on `main` yet. The two deliverables:

### 1. Root linting — Biome

Picked **Biome** over ESLint+Prettier: one dependency instead of ~5+
(`eslint`, `prettier`, `@typescript-eslint/*`, `eslint-config-prettier`, ...), which
matches the scaffold's stated convention of "keep root devDependencies to repo
tooling only." Biome also does lint + format + import-organize in a single fast pass,
which suits a monorepo where `packages/wire` doesn't exist yet — there's nothing to
run it against per-package right now, but the root config is ready for every package
that lands afterward.

- **`package.json`**: added `@biomejs/biome: ^2.5.4` to `devDependencies`; changed
  `"lint"` from `"turbo run lint"` to `"biome check ."`, added `"lint:fix": "biome
  check --write ."`.
  - **Why not route lint through turbo** (deviates from the turborepo skill's
    "root scripts only delegate to `turbo run`" guidance): Biome is a single
    whole-repo tool with its own fast crawler/cache, not a per-package build step —
    there's no per-package `lint` script to fan out to yet (no packages exist), and
    when packages do land, most won't need their own bespoke lint step since Biome
    already covers the whole tree in one pass. `turbo.json`'s existing `"lint"` task
    (added by the scaffold task) was intentionally left untouched/unwired — it's
    available for a future package that needs a framework-specific lint step
    (e.g. `next lint` for `packages/web`) on top of the root Biome pass, without
    forcing Biome itself through turbo's per-package graph.
- **`biome.json`** (root): `vcs.enabled: false` — see the debugging note below for
  why. `files.includes` hand-excludes everything `.gitignore` also excludes
  (`node_modules`, `dist`, `build`, `.turbo`, `coverage`, `*.tsbuildinfo`,
  `pnpm-lock.yaml`, `.worktrees`, `happy`, `superset`, `.vscode`, `.idea`) plus
  `.claude` (the `falcon-dev-loop` orchestration script living at repo root —
  infra, not Falcon product code, and out of this task's scope to fix/reformat).
  Linter: `preset: "recommended"` (Biome 2.5's replacement for the deprecated
  `recommended: true` field — found via `biome migrate --write`) plus a few explicit
  opinions matching `tsconfig.base.json`'s strictness: `noUnusedVariables`/
  `noUnusedImports` as errors, `useImportType` as error (matches `isolatedModules:
  true`), `noExplicitAny`/`noNonNullAssertion` as warnings (Falcon's design leans
  null-safe, per `falcon-system-design.md`, but a hard error would block
  legitimate escape hatches during early scaffolding). Formatter: 2-space indent,
  100-char line width, double quotes, always-semicolons, all-trailing-commas —
  matches the style already used throughout `happy/` source and this repo's own
  `.claude/workflows/falcon-dev-workflow.js`.
  Import-organizing enabled via `assist.actions.source.organizeImports: "on"`
  (auto-fixable on `lint:fix`).

  **Debugging note — why `vcs.enabled: false` instead of the more idiomatic
  `vcs: { enabled: true, clientKind: "git", useIgnoreFile: true }`:** with VCS
  integration on, `biome check .` reliably crashed with `[warn] Linter process
  terminated abnormally (possibly out of memory)` in this worktree. Root-caused it
  to Biome's git integration choking on a **git worktree's `.git` file** (worktrees
  have a `.git` *file* containing `gitdir: <path>`, not a `.git` *directory* like a
  normal checkout) — reading a single file with an explicit path worked fine
  (`biome check package.json`), but any project-wide crawl (`biome check .`, or even
  `--verbose` on a single file) triggered the crash, consistent with Biome's VCS
  layer mis-walking the repo and falling into runaway recursion through
  `node_modules/.pnpm`'s symlink graph. Disabling VCS integration and hand-listing
  every ignore pattern in `files.includes` sidesteps the bug entirely, is git-worktree-
  agnostic (works identically for the CI checkout, a plain clone, or any worktree),
  and was confirmed clean: `pnpm lint` → `Checked 4 files … ` with zero warnings.

  **Second gotcha, also worktree-specific:** an early version of `files.includes`
  used `"!**/happy"`, `"!**/superset"`, `"!**/.worktrees"` (the `**/` prefix matches
  the pattern at *any* path depth). Because this worktree's own absolute path is
  `.../vibe-ide/.worktrees/P0-0.1-ci-tooling`, the `**/.worktrees` pattern matched
  an *ancestor* segment of the project root itself, so Biome considered the entire
  project excluded (`Checked 0 files`). Fixed by anchoring those three patterns to
  the project root (`"!.worktrees"`, `"!happy"`, `"!superset"`, no `**/` prefix) —
  they only ever live at repo root per `.gitignore`, so root-anchoring is also more
  correct, not just a workaround. Verified by running `biome check .` from inside
  this worktree without it misfiring.

### 2. CI workflow

**`.github/workflows/ci.yml`** — runs on `pull_request`/`push` to `main`:
`checkout` → `pnpm/action-setup@v4` (reads the pinned version from
`package.json`'s `packageManager` field) → `actions/setup-node@v4` (Node 20,
`cache: pnpm`) → `pnpm install --frozen-lockfile` → `pnpm lint` → `pnpm --filter
@falcon/wire build` → `pnpm typecheck` → `pnpm test`. `concurrency` group cancels
stale runs on the same ref (superseded pushes to a PR don't queue).

- Lint step added ahead of the task description's literal `install → build wire →
  typecheck → test` sequence (inserted right after install) — pairs the two halves
  of this task together (setting up a linter with no CI step to enforce it would be
  dead weight) and fails fast before the more expensive build/test steps.
- `pnpm --filter @falcon/wire build` (not `pnpm build`) matches the task's literal
  wording and plan.md §1's framing of wire as the first, foundational build
  milestone. It's currently a graceful no-op (`pnpm --filter` on a non-matching
  package name exits 0 with a warning, unlike `turbo --filter` which exits 1) —
  confirmed no packages exist yet, so this step passes today and will start doing
  real work the moment `packages/wire` lands (0.2). `pnpm typecheck`/`pnpm test`
  (unfiltered, via turbo) will build every other package's dependencies internally
  once they exist, since `typecheck`'s `dependsOn: ["^build"]` already covers that;
  the dedicated wire-build step exists purely as an early, isolated gate on the one
  package everything else depends on.
- No remote-cache (`TURBO_TOKEN`/`TURBO_TEAM`) wiring — no Vercel remote-cache
  account exists for this project yet; can be added later without touching the
  rest of the workflow.

## Verification

Ran in the worktree (via `rtk proxy pnpm <script>` — see note below):
- `pnpm install` → succeeds, `@biomejs/biome 2.5.4` installed, lockfile updated.
- `pnpm lint` → `biome check .` → `Checked 4 files in 2ms. No fixes applied.` (no
  errors, no warnings, no deprecation notices).
- `pnpm --filter @falcon/wire build` → exits 0 (`No projects matched the filters`,
  expected — package doesn't exist yet).
- `pnpm build` → `turbo run build` → exit 0, "0 packages" (same expected no-op as
  the scaffold task's own verification).
- `pnpm typecheck` → exit 0.
- `pnpm test` → exit 0.
- `.github/workflows/ci.yml` parses as valid YAML; steps mirror the exact commands
  verified above so a PR run should reproduce the same result (the GitHub Actions
  runner has no `rtk` hook, so this local workaround is a non-issue there).

**Local-environment note (not a repo issue):** in this sandbox, Bash invocations are
intercepted and rewritten by a local `PreToolUse` shell hook (`rtk hook claude`, a
token-optimization CLI proxy configured in this machine's global
`~/.claude/settings.json` and documented in `~/.claude/RTK.md`) — this rewriting
applies to *every* Bash command in the session, not just `pnpm`-script invocations.
Its own process wrapping intermittently crashed the child `biome check` process
(`[warn] Linter process terminated abnormally (possibly out of memory)`) for `pnpm
lint` **and equally for `npx biome check .` run directly** (confirmed by testing
both) — `npx` is not a clean bypass of the hook, since the hook rewrites the Bash
call itself regardless of which command it wraps. The only reliable way to see the
raw, unrewritten command run — and confirm the tool works correctly, which it does
cleanly in every case tested — was `rtk proxy <cmd>`. This exact symptom is already
called out in the sibling `P0-0.1-monorepo-scaffold` task-summary for `pnpm lint`/
`turbo run lint`, so it's a pre-existing characteristic of this sandbox, not
something introduced here, and it does not affect GitHub Actions CI runners, which
have no such hook. Verified all scripts pass cleanly via `rtk proxy pnpm <script>`
(bypasses the hook) — see the exit codes above.

## Assumptions

- Biome chosen over ESLint+Prettier per the task's "pick one" instruction — no
  existing lint config in `happy/` to port from (verified: no `.eslintrc*`,
  `eslint.config.*`, or `.prettierrc*` anywhere in `happy/`), so this is a fresh
  choice rather than a port.
- `@biomejs/biome` pinned to `^2.5.4` (latest stable at the time of this task,
  confirmed via `npm view @biomejs/biome version`).
- CI workflow targets `pull_request`/`push` to `main` only (no other long-lived
  branches exist yet in this repo's branching model).
- `.claude/` (the `falcon-dev-loop` orchestrator script) is excluded from Biome's
  scope as external tooling infrastructure, not Falcon product code — left
  unmodified even though it has pre-existing style/lint deviations (e.g. an
  optional-chain opportunity in `falcon-dev-workflow.js`), since fixing it is out
  of this task's scope and it's shared across every sibling worktree.
- Left `turbo.json`'s `"lint"` pipeline task as originally added by the scaffold
  task, unwired to any root script for now — reserved for a future package that
  needs a lint step beyond what root-level Biome already covers.
