# P3-3.3-web-unmanaged-section

Web: unmanaged-session section, live mirror view, and Take Over / Fork Instead dialog
(plan.md §16 "3.3 Session adoption (UC9)", last bullet; falcon-system-design.md §8/§9.2/§10.4/§11).

## What was built

**`packages/web/src/features/unmanaged-sessions/`** — new feature, following the same
injectable-seam pattern as `features/session-list`, `features/new-session`, and
`features/session-control` (mock data source by default, a `live-actions.ts` adapter
swapped in once a screen has a live `apiSocket` + per-machine crypto client — none of
that wiring exists on `main` yet for *any* feature, so this one matches the codebase's
current maturity level rather than jumping ahead of it):

- `types.ts` — `UnmanagedSessionItem` (decrypted view-model mirroring
  `@falcon/wire`'s `UnmanagedSessionRow` + its decrypted `summary`), `UnmanagedActions`
  (`mirror`/`take`), `UseUnmanagedSessionsSnapshot` / `UseUnmanagedActions` seams.
- `mock-source.ts` — a two-row fixture (one `running: true`, one idle) plus mock
  `mirror`/`take` implementations (the mock `mirror` even chunks its canned transcript
  into small pieces so the cursor-following logic in `mirror.ts` is exercised against it,
  not just the real RPC path).
- `live-actions.ts` — `machineRpcToUnmanagedActions(rpc)`, a one-line adapter from
  `MachineRpcClient` to `UnmanagedActions`, calling the `adopt.mirror`/`adopt.take`
  machine RPCs (mirrors `features/new-session`'s `machineRpcToActions`).
- `mirror.ts` — pure helpers: `fetchFullTranscript` (loops `adopt.mirror` from cursor 0
  until `done`, with a `MAX_CHUNKS` safety cap so a daemon bug that never reports `done`
  throws instead of looping forever) and `parseMirrorLines` (a small, browser-side,
  self-contained JSONL parser — deliberately *not* imported from
  `packages/cli/src/daemon/transcriptIndexer.ts`'s `extractText`/`parseTranscript` since
  that module is Node-only; the ~15-line pure parsing logic is duplicated here instead).
- `use-mirror-transcript.ts` — `useMirrorTranscript`, a `useQuery`-backed poll
  (4s interval, `refetchOnWindowFocus`) that re-reads the full transcript from cursor 0
  each cycle and parses it into a line feed; never clears previously-rendered lines on a
  transient poll failure (design §9.1 "never show a loading error — retry silently").
- `components/unmanaged-section.tsx` — the Home-screen section (design §9.2's
  `UnmanagedSection`), sorted by most-recent activity, hidden entirely when empty.
- `components/unmanaged-session-card.tsx` — one row: running/idle pulse dot, machine
  badge, relative time, a "View" link to the mirror route, and a "Take over" button.
- `components/take-over-dialog.tsx` — the Take Over / Fork Instead dialog: choose mode →
  (takeover-while-running only) an extra "still running, are you sure" confirm step →
  calls `actions.take` → success state with a `warning` banner (mid-turn interrupt) and an
  "Open session" link to `/session/<newSessionId>/`.
- `components/mirror-view-screen.tsx` — the live read-only mirror screen: header
  (title, running/idle + machine name, "Take over" button reusing the same dialog),
  scrollable line feed (`useMirrorTranscript`), not-found state for an unknown id.
- `index.ts` — barrel, same convention as the other features' `index.ts`.
- `__tests__/mirror.test.ts` — unit tests for `fetchFullTranscript` (chunk
  concatenation, `nextCursor: null` early-stop, the `MAX_CHUNKS` guard) and
  `parseMirrorLines` (user/assistant text extraction, array-content blocks, raw
  fallback for unparsable/unrecognized lines).

**Wiring into the existing session-list feature:**

  `P3-3.3-adopt-cli-and-take-rpc` and `P3-3.3-session-adoption-indexer` tasks — this
  task only had to add the caller-side typing, the daemon-side registration in
  `packages/cli/src/daemon/machineRpc.ts` was already there). Added matching test cases
  to `sync/__tests__/machineRpc.test.ts`.
- `sync/index.ts` — exports the two new param types.

**New shadcn/ui primitive:**
- `components/ui/dialog.tsx` — a standard shadcn Dialog wrapping
  `@radix-ui/react-dialog` (added as a new dependency to `packages/web/package.json`;
  no Dialog primitive existed in the repo before this task). Follows the same
  `data-slot`/`cn()` conventions as the existing `collapsible.tsx`/`card.tsx`/`badge.tsx`.

**New route:**
- `app/session/unmanaged/[id]/page.tsx` — the mirror view's route, following the exact
  same static-export precedent as `app/session/[id]/page.tsx`: `generateStaticParams`
  returns only `{id: "demo"}` (real ids come from a not-yet-wired sync-engine snapshot),
  and every other id is reached via client-side navigation from `UnmanagedSection`'s
  "View" link — the same precedent `features/new-session`'s post-spawn "Open session"
  link already relies on.

## Design decisions / assumptions

- **"Live" = poll-and-replace, not tail-and-append.** `adopt.mirror`'s `cursor` is a
  byte-offset pagination cursor into *one* read of the transcript file, not a
  follow/tail position (per its own wire doc comment). So "live" here means: on each
  poll tick, re-read the whole file from cursor 0 through however many chunks it takes
  to reach `done: true`, and re-render. This matches the design doc's own "bandwidth +
  privacy frugality" framing for an on-demand mirror (§8) — it's simple and correct,
  just not incremental. A future task could add a `since`/tail cursor to the wire
  contract if 4s full-reread polling turns out to be too chatty for large transcripts.
- **Transcript rendering is a lightweight JSONL line parser, not the full reducer.**
  The mirror shows a plain-`claude` transcript in Claude Code's own JSONL format, which
  is a different shape from `@falcon/wire`'s `SessionEnvelope` the timeline's
  `reduceEnvelopes`/`Timeline` pipeline consumes. Building a full envelope mapper for
  raw Claude Code JSONL (title: "import history" mapping) is explicitly the CLI-side
  `falcon adopt` command's job per design §7.8 ("import history: stream `importTranscript`
  envelopes"), already landed. Re-deriving that mapping in the browser for a read-only
  mirror would duplicate real business logic; instead this renders a minimal
  role+text-per-line feed (user/assistant text, or the raw JSON line as a fallback for
  anything else — tool calls, thinking blocks, summaries, ...). This keeps the mirror
  genuinely "minimal" per the task's scope (a read-only reflection) without pretending
  to be the full structured timeline.
- **Takeover confirm step only gates the destructive path.** Per design §10.4 ("phone:
  'Take over' → confirm (mid-turn warning if running)"), the dialog only inserts an
  extra confirmation screen when `mode === 'takeover'` **and** `session.running` — a
  fork never touches the original process, so it goes straight to the RPC call; an
  idle session's takeover has nothing running to interrupt, so it also skips the extra
  step.
- **`UnmanagedSection`/`UnmanagedSessionCard` call their `useActions` hook at the
  component's own top level**, not from inside a `.map()` in the parent — since
  `UseUnmanagedActions` is typed and named like a hook (mirroring
  `UseNewSessionActions`), and the real eventual implementation will very likely use
  React state/memoization internally, each card calls it once, unconditionally, in its
  own component instance (Rules-of-Hooks-safe), rather than the parent calling it once
  per session inside a loop (which would not be).
- Reused `SessionListMachine`/`MachineBadge`/`formatRelativeTime` from
  `features/session-list` rather than duplicating machine-badge/relative-time
  formatting — same machines, same presentation.

## Verification

- `pnpm build` (root, `turbo run build`, forced/no cache) — 5/5 packages green, including
  the new `/session/unmanaged/[id]` static route (prerenders `/session/unmanaged/demo`).
- `pnpm typecheck` — all packages green.
- `pnpm test` — all packages green (`@falcon/web`: 36 files / 298 tests, up from 35/289 —
  the new `mirror.test.ts` (9 tests) plus 2 new `machineRpc.test.ts` cases).
- `pnpm exec biome check` on every touched/new file — clean (repo-wide `biome check .`
  still reports its pre-existing, unrelated warnings/errors in `packages/cli/src/daemon/`
  files this task never touched — not introduced by this change).

## Not in scope / left for later

- Wiring `UnmanagedSection`'s default `useSnapshot` to the real sync engine (the
  `unmanagedSessions` field is already present on `SyncSnapshot` and already
  handled by `sync/engine.ts`'s `unmanaged-new`/`unmanaged-update` fast path — this
  task only needed the UI, not that wiring) and wiring `useMockUnmanagedActions`/
  `machineRpcToUnmanagedActions` to a live `apiSocket` + per-machine crypto client are
  both the same "not yet wired anywhere in the app" gap every other feature in
  `packages/web/src/features/` currently has — tracked generally, not specific to this
  task.
- `adopt.mirror`'s `blobRef` large-transcript fallback (unset/unimplemented end-to-end
  per its own wire doc comment) — the mirror view only ever exercises the inline-chunk
  path, same as the daemon side.
