# P3-3.3-adopt-cli-and-take-rpc

`falcon adopt` / `--continue` CLI, `adopt.take` RPC, and chunked read-only
transcript mirror — plan.md §16 "3.3 Session adoption (UC9)", the three
remaining bullets after the transcript indexer (`P3-3.3-session-adoption-indexer`,
merge `fa3990e`, already on `main`).

## What was built

### 1. Wire schema additions (`packages/wire/src/rpc.ts`)

- `AdoptTakeResultSchema` gained an additive optional `warning?: string` —
  set when a `'takeover'` actually interrupted a live, possibly mid-turn
  process (design §10.4/FR-9.3).
- New `AdoptMirrorParamsSchema`/`AdoptMirrorResultSchema`: `{idempotencyKey,
  providerSessionId, cursor?, maxBytes?}` → `{chunk, nextCursor, done,
  blobRef?}`. `blobRef` is a reserved field for the future blob-storage
  fallback (not implemented — see below); the chunked path already serves
  transcripts of any size correctly, just over more round-trips.
- Both registered in `__tests__/schemaRegistry.ts` and re-frozen into
  `wire-shapes.json` via `scripts/snapshot-shapes.ts` (additive-only compat
  test passes).

### 2. Chunked read-only transcript mirror (`daemon/transcriptMirror.ts`, new)

`handleAdoptMirror(params, deps)`: resolves `providerSessionId` to a
workspace via the injected `resolveProviderSession` seam, reads the
transcript file, and returns one chunk starting at `cursor` (default 0).
`findChunkEnd` (exported, unit-tested) clamps to ≤64KB but always pulls the
cut back to the nearest preceding newline — so a chunk boundary never
splits a JSONL line or a multi-byte UTF-8 character. Paginating by
repeatedly requesting `cursor: nextCursor` reconstructs the file exactly,
byte for byte, verified in tests. Throws (never silently returns empty) if
the provider session can't be resolved, the file can't be read, or
`cursor` is past EOF.

### 3. `adopt.take` RPC core (`daemon/adoptTake.ts`, new)

`handleAdoptTake(params, deps)`:
- `mode: 'takeover'` — finds the live, non-Falcon `claude` process owning
  the transcript (`adopt/liveness.ts`'s `findOwningClaudeProcess`, same
  heuristic as the transcript indexer's private `computeRunning`:
  live-process-cwd-matches-workspace paired with the most-recently-modified
  transcript in that project dir), SIGTERM it, wait up to
  `gracefulTimeoutMs` (default 5s, polled), SIGKILL fallback if still alive
  — reusing `kill.ts`'s OS-level primitives (`createKillDeps`) rather than
  duplicating them. Sets a `warning` on the result when a live process was
  actually found/killed (there's no way to know from the transcript alone
  whether its *last* turn had finished, so any live process is treated as
  "possibly mid-turn").
- `mode: 'fork'` — skips the kill/liveness check entirely.
- Both modes then call the injected `spawnSession` with
  `continueFrom: {providerSessionId}`, `provider: 'claude-code'`,
  `permissionMode: 'default'`, and the *same* `idempotencyKey` from the
  RPC params (Codex adoption is out of scope per the PRD: "Codex adoption
  may ship as import-of-finished-sessions only at MVP").
- Idempotency-key *replay* itself is NOT implemented inside this module —
  it's `machineRpc.ts`'s job (see below), matching the existing convention
  `spawnEngine.ts` already established for `spawn`.

### 4. `daemon/providerSessionResolver.ts` (new, shared seam)

`ProviderSessionResolver = (providerSessionId) => Promise<{workspaceId,
directory} | null>`, used by both `adoptTake.ts` and `transcriptMirror.ts`.
No real default is provided — same documented pattern as
`workspacePath.ts`'s `resolveWorkspaceRoot` and `transcriptIndexer.ts`'s
`listWorkspaces`: real workspace-registration bookkeeping is a separate,
later task (§3.1's spawn-flow work), and this seam composes with it the
same way once it lands.

### 5. `machineRpc.ts` generalized to a real multi-method dispatch table

Was previously spawn-only with hard-coded `method !== "spawn"` checks. Now:
- `MACHINE_RPC_METHODS = ["spawn", "adopt.take", "adopt.mirror"]`.
- A generic `dispatch<P,R>()` helper runs the
  decrypt→validate→handle→validate-result→seal pipeline for any method,
  called once per case in `onRpcRequest`'s switch (kept as a switch rather
  than a heterogeneous `Record` table, to stay type-safe without `any`/
  unsafe casts).
- `MachineRpcDeps` gained two new required fields: `adoptTake` and
  `adoptMirror` (mirroring `spawnSession`'s existing shape) — each wrapped
  in its own `withIdempotencyCache()` Map, same semantics as the pre-existing
  spawn cache (never caches a rejected call).
- All pre-existing spawn tests still pass unmodified in spirit (the test
  file was restructured with a `register()`/`baseHandlerDeps()` helper so
  every test supplies `adoptTake`/`adoptMirror` stubs alongside
  `spawnSession`); 22 tests now cover all three methods including
  idempotency-replay and error-shape parity.
- **Expected reconciliation at land time**: the durability task
  (`stopSession`/`resumeSession`) also touches this file's method table —
  same shape extension, disjoint methods, should merge cleanly per the
  file's own doc comment inviting exactly this kind of addition.

### 6. `falcon adopt [--remote] [--list]` + `falcon --continue` (new)

- `packages/cli/src/adopt/listSessions.ts`: local (no network) enumeration
  of plain Claude Code transcripts for cwd's workspace, reusing
  `transcriptIndexer.ts`'s exported `parseTranscript` + `scanner.ts`'s
  `getProjectPath`, sorted most-recent-first, with a `running` flag derived
  from `adopt/liveness.ts`.
- `packages/cli/src/adopt/liveness.ts`: `findOwningClaudeProcess` +
  `isPlainClaudeCommand`, a standalone reimplementation of the transcript
  indexer's private liveness heuristic (duplicated rather than exported
  from `transcriptIndexer.ts`, per the task brief's scope boundary —
  kept in lockstep by design, documented in both places).
- `packages/cli/src/adopt/lineage.ts`: `recordAdoptionLineage`/
  `getAdoptionLineage`, backed by a new `adoptedSessions?: Record<string,
  string[]>` field on `persistence.ts`'s `Settings` (schema-versioned,
  atomic read-modify-write reused as-is — no new lock/tmp-file machinery
  needed).
- `packages/cli/src/commands/adopt.ts`: the command itself.
  - `--list`: prints the list, no side effects.
  - Default (local): spawns `claude --resume <id>` with **inherited
    stdio**, blocking until it exits — a real, working resume, not a stub.
    Snapshots the project dir's `.jsonl` ids before the child runs, diffs
    after it exits to discover the new id Claude Code's `--resume` mints
    (plan.md §11: "Session Forking"), and records the lineage. No hook
    server needed for this path — the exact id being resumed from is
    already known going in, so id discovery is a simple before/after
    filesystem diff.
  - `--remote`: launches `falcon claude --starting-mode remote
    --continue-from <id>` **detached** (reusing `processLauncher.ts`'s
    tmux-preferred/detached launcher and the same falcon-entrypoint
    re-invocation trick `spawnEngine.ts` uses) instead of blocking the
    terminal. Lineage recording for this path is honestly deferred (no
    hook wired to an ad hoc detached launch to learn the new id
    synchronously) — an explicit note is printed rather than silently
    skipping it.
- Wired into `args.ts` (`parseAdopt`, `{type:"adopt", list, remote}`) and
  `index.ts` (`runAdopt`, gated by `ensureDaemon()` like every other
  agent-adjacent subcommand). `falcon --continue` is a top-level flag
  check (alongside `--help`/`--version`) that delegates to the same
  `parseAdopt` parser, so `falcon --continue --remote` composes exactly
  like `falcon adopt --remote`.
- Help text updated.

## Assumptions / scope decisions

- **Codex adoption is out of scope** (per PRD §4: "Codex adoption may ship
  as import-of-finished-sessions only at MVP") — `adoptTake.ts` always
  spawns `provider: 'claude-code'`.
- **`blobRef` on `AdoptMirrorResultSchema` is unimplemented** — blob
  storage itself doesn't exist yet anywhere in this codebase (plan.md §16
  "4.3 Distribution & self-host" is still unchecked). This mirrors the
  exact precedent already set by `GitDiffResultSchema`/`FsReadResultSchema`,
  which ship the same kind of not-yet-wired `blobRef` field. The chunked
  path is fully correct and complete for its documented scope (any
  transcript size, just more round-trips) — the blob path is a later
  bandwidth optimization, not a correctness gap.
- **`resolveProviderSession` has no real default** — same seam pattern the
  indexer task already established for `listWorkspaces`/`isManaged`.
  Wiring real workspace-registry lookups into `adoptTake.ts`/
  `transcriptMirror.ts`/`machineRpc.ts`'s daemon bootstrap is follow-up
  work once the spawn-flow's workspace registry (§3.1) lands.
- **`falcon adopt`'s local resume is a direct, minimal `claude --resume
  <id>` child spawn** — deliberately NOT routed through `claude/claudeLocal.ts`'s
  heavier launcher (hook-settings file, `falcon_claude_launcher.cjs`,
  fetch-patch pipe for a `thinking` signal), since none of that machinery
  is needed here: the provider session id being resumed is already known
  going in, so there's no hook-based id-discovery problem to solve. This
  also matches the codebase's current reality that `falcon claude`'s own
  full orchestration isn't wired into `runStart` yet either.
- **Mid-turn detection is best-effort** ("any live process owning the
  transcript is treated as possibly mid-turn") — there's no way to know
  from the transcript file alone whether the process's last turn had
  actually finished; the warning errs toward over-informing rather than
  silently under-informing.
- Web-side unmanaged-section UI (live mirror view, Take-over/Fork-Instead
  dialog) is explicitly out of scope per the task brief — it depends on
  this RPC work and is a separate, later bullet.
