# U1.1 — "wave1-trivia" (inline)

Three unrelated micro-fixes from plan-v2.md's Wave 1, batched into one pass
because each is a one-file, few-line change with its own tiny test.

## P1.0 — postinstall spawn-helper chmod guard

**Why.** `node-pty`'s native `spawn-helper` binary (macOS only — used to spawn
the PTY child through a login shell) is sometimes restored by pnpm's
content-addressable store without its executable bit, silently breaking every
local PTY session until someone `chmod +x`s it by hand. plan-v2.md flagged
this as Wave-1 risk #5: fold the fix into `scripts/postinstall.cjs` so a
fresh `pnpm install` can't reintroduce it.

**What.** `scripts/postinstall.cjs` now also walks
`node_modules/.pnpm/node-pty@*/node_modules/node-pty/` recursively for any
file literally named `spawn-helper` and `chmod 0o755`s it, after the existing
`@falcon/wire` build step. Wrapped in try/catch so a weird store layout never
fails the whole install — it just warns. A no-op on Linux (no such directory)
and everywhere `SKIP_FALCON_WIRE_BUILD=1` is set (the guard still runs; only
the wire build is skipped).

**Verified for real**: a full `pnpm install --frozen-lockfile` in the
worktree exercised the new code path and actually chmod'd
`node_modules/.pnpm/node-pty@1.1.0/node_modules/node-pty/prebuilds/{darwin-arm64,darwin-x64}/spawn-helper`
to `-rwxr-xr-x` (confirmed via `stat`) — this is real coverage of the actual
current node-pty package layout, not just a guess at the plan's example path.

## W1.7a — `ThinkingBlock.tsx` collapsed label

**Why.** The collapsed trigger always read the present-tense "Thinking…",
even for a block that's been fully rendered for hours — the reducer only
ever emits *complete* thinking envelopes, so a rendered `ThinkingBlock` is
always historical. The live "thinking now" signal belongs to the in-timeline
activity row (W1.8, already landed), not this label.

**What.** Extracted the label as its own exported pure function
`thinkingBlockLabel(open: boolean)` in `ThinkingBlock.tsx` (open → "Hide
thinking", closed → "Thought process"), used directly in the JSX. Kept it in
the same file rather than a sibling module (unlike `session-control`/
`session-list`'s kebab-case-`.ts` convention) since `components/timeline/`
has no such sibling-logic file precedent and the function is a two-line,
component-local concern.

**Tests.** `ThinkingBlock.test.ts` (new) — collapsed vs. open label.

## W1.7b — `use-session-ephemerals.ts` 60s staleness cap

**Why.** The `activity` ephemeral (`working: true/false`) is explicitly
droppable/coalesced by design (§4.3) — but the hook trusted a `working:true`
forever if its matching `working:false` was ever dropped (daemon crash,
missed socket message), pinning "Working…" on the timeline indefinitely.

**What.** Added `WORKING_STALE_MS = 60_000` and a pure predicate
`isWorkingFresh(workingSince, now)`. The hook now records `workingSince` in a
ref on every `working:true` event, clears/reschedules a `setTimeout` on every
event, and — when the timeout fires with no successor — re-checks
`isWorkingFresh` before flipping `working` back to `false` (rather than
blindly trusting the timer fire), so the exact same staleness logic backs
both the test and the real hook.

**Tests.** `use-session-ephemerals.test.ts` (new) — `isWorkingFresh` at
`null`, immediately-fresh, just-under-cap, exactly-at-cap, and well-past-cap.
