# P1-1.6-reducer-port — Sync reducer port: SessionEnvelope[] → render items

## What this is

Ports the *logic* of Happy's `happy-app/sources/sync/reducer/reducer.ts` (plan.md
§8.2, falcon-system-design.md §9.1) into `packages/web/src/sync/reducer/`. This
directory did not exist on `main` before this task.

**Note on source access:** the Happy source tree (`happy-app/`) was not present
anywhere on this machine (verified via filesystem search) and this task doesn't
depend on any other unmerged worktree, so this is a from-spec reimplementation
guided by plan.md §8.2, falcon-system-design.md §9.1 (which spells out the exact
behaviors: "turn grouping, tool-start/end pairing, perm-request/resolve pairing
(by reqId; fallback name+args match), subagent nesting, dedupe by envelope id")
and the already-merged `@falcon/wire` `SessionEnvelopeSchema`/`SessionEventSchema`
(a flatter, provider-agnostic event model than Happy's nested React Native
content-block messages — see `packages/wire/src/session.ts`). The four behaviors
plan.md calls out as load-bearing were preserved faithfully; the render-item
*shape* is a fresh design fit to Falcon's flatter wire schema (documented in
`types.ts`).

## Files

- `packages/web/src/sync/reducer/types.ts` — `RenderItem` discriminated union
  (`text`, `service`, `file`, `turn-start`/`turn-end`, `mode-switch`,
  `sub-start`/`sub-stop`, `perm-placeholder`, `tool`, `orphan-tool-end`,
  `subagent-group`) plus the shared `PermissionInfo` shape.
- `packages/web/src/sync/reducer/reduce.ts` — `reduceEnvelopes(envelopes)`, the
  pure transform. Multi-phase:
  1. **Dedupe by envelope id** (first occurrence wins — a reconnect/re-fetch
     merge may repeat ids).
  2. **Stable time-sort.**
  3. **Partition into scopes** by `envelope.subagent` (root scope = no
     subagent).
  4. **Reduce each scope**: tool-start/tool-end pairing by `call`;
     perm-request↔tool-start matching — direct by `call` id when the
     perm-request already knows it, else a **name+args fallback match** against
     a FIFO queue of unmatched placeholders (key-order-independent canonical
     JSON key); perm-resolve updates the shared `PermissionInfo` object
     wherever it ended up (placeholder or tool) so match order never matters.
     Unresolvable data is never dropped: a `tool-end` with no known `call`
     becomes `orphan-tool-end`; a `perm-request` that never matches becomes a
     standalone `perm-placeholder`.
  5. **Link subagent scopes**: a subagent's envelopes nest under the `ToolItem`
     whose `call` equals the subagent id (documented assumption: adapters mint
     `envelope.subagent` as the parent Task-like tool's `call` id — the natural
     choice since the wire schema gives no other explicit link). The search is
     recursive over the whole tree (including already-linked nested
     subagents), so linking is independent of scope processing order. Scopes
     that never find a parent tool are still surfaced as standalone
     `subagent-group` items rather than dropped.
- `packages/web/src/sync/reducer/index.ts` — public exports.
- `packages/web/src/sync/reducer/reduce.test.ts` — 12 focused unit tests:
  dedupe, stable ordering, tool-start/end pairing (+ orphan), both permission
  match paths (call-id direct, name+args fallback incl. key-order
  independence + FIFO), unmatched-placeholder persistence, subagent linking
  (direct, standalone, and nested subagent-of-subagent), and event
  pass-through.
- `packages/web/src/sync/reducer/golden.test.ts` — the golden-trace harness:
  reads every `__testdata__/trace_*.json`, validates its `envelopes` through
  `SessionEnvelopeSchema` (a malformed fixture fails loudly, not silently),
  runs `reduceEnvelopes`, and deep-equals the result against the fixture's
  `expected` tree. Also asserts at least one fixture exists, so an emptied
  `__testdata__/` fails the suite rather than passing vacuously.
- `packages/web/src/sync/reducer/__testdata__/trace_*.json` (6 fixtures) — one
  golden trace per representative scenario: basic turn/tool pairing, perm
  placeholder → name+args match → resolve, perm request with a known call id,
  subagent/Task linking, dedupe+reorder (simulated reconnect merge), and
  orphan-tool-end + unresolved-placeholder (no-silent-failure cases). This is
  Happy's `trace_*.json` fixture convention, ported; grow this directory with
  every new provider quirk found (plan.md's cross-cutting rule).
- `packages/web/package.json` — added `@falcon/wire` as a dependency (was
  missing; every other consumer of the wire schemas already depends on it).

## Assumptions / design notes

- **Subagent-to-tool linking key**: the wire schema (`session.ts`) gives no
  explicit field tying a `subagent` id to the tool call that spawned it. I
  assumed the adapter convention is `subagent id == parent tool's call id`
  (the natural, zero-extra-field choice) and linked on that. If adapters end
  up minting an unrelated subagent id, this degrades gracefully — the scope is
  still rendered, just as a standalone `subagent-group` instead of nested
  under its parent — so nothing is lost, only less deeply nested.
- **Turn grouping**: kept minimal — every render item carries the source
  envelope's `turn` id (pass-through) and `turn-start`/`turn-end` are their own
  boundary items. I did not nest items into a `TurnGroup` wrapper; that's a
  timeline-UI presentation decision explicitly out of scope for this task
  ("Do not wire into … timeline UI screens").
- **Perm-resolve with an unknown `reqId`** (arrives with no prior
  perm-request) is a silent no-op — there's no render target for it and
  nothing meaningful to surface; this mirrors the "unwrap never throws /
  best-effort" philosophy without inventing a phantom item.
- Not wired into the sync engine, session list, or timeline UI — per the task
  boundary, this is pure logic tested in isolation against hand-built envelope
  arrays.
