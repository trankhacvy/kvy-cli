# U4.2 — render-polish (W4.2a)

Bundle unit, `packages/web` only. No prior commits existed on this branch
(`git log v2-pty-injection..HEAD --oneline` was empty at start) — built from
scratch against plan-v2.md's Wave 4 §4.2 section.

## Sub-tasks landed

1. **Timestamps** — `lib/format.ts` gained `shouldShowHourDivider`,
   `formatHourDividerLabel`, `formatFullTimestamp` (local-wall-clock hour
   bucketing, `en-US`-pinned `Intl.DateTimeFormat`). Wired into
   `Timeline.tsx`'s per-row wrapper: a `title` attribute (hover tooltip) with
   the full timestamp, plus a new `HourDivider.tsx` rendered before the first
   item of each new local hour.
2. **`CopyButton`** — one shared component (`components/timeline/CopyButton.tsx`,
   `navigator.clipboard.writeText` + a 1.5s "Copied" flash), used in three
   places per the plan:
   - `MessageText.tsx` — hover-reveal button on the message bubble, copies
     `item.md` (raw markdown/text).
   - `CodeBlock.tsx` — new `rehype-react` `pre` override wired into
     `lib/markdown.ts`'s pipeline (`components: { pre: CodeBlock }`); reads
     `pre.textContent` from the live DOM at click time rather than
     re-serializing shiki's per-token `<span>` tree.
   - `BashCard.tsx` — copies the parsed Bash command (only rendered when a
     command was actually captured).
3. **Theme toggle** — `layout.tsx`'s hardcoded `className="dark"` replaced
   with `DEFAULT_THEME`-driven default + a pre-hydration anti-flash script
   (next-themes' own pattern: reads `localStorage`, strips `.dark` before
   first paint if the stored preference is `"light"`). New
   `settings/appearance/page.tsx` (same auth-gate pattern as
   `settings/notifications`) with Dark/Light buttons, backed by
   `lib/use-theme.ts` (a `useSyncExternalStore` store, same shape as the
   existing `document-title-store.ts`) and `lib/theme.ts` (pure
   `parseTheme`/`toggleTheme`/constants, fully unit-tested).
4. **Dual shiki theme** — `lib/markdown.ts`'s `theme: "github-dark"` →
   `theme: { light: "github-light", dark: "github-dark" }`. Verified via a
   throwaway probe (deleted before commit) that rehype-pretty-code's
   multi-theme mode emits *only* `--shiki-light`/`--shiki-dark` CSS custom
   properties per token (no literal `color:` fallback — `defaultColor` is
   forced `false` whenever `theme` is an object, per rehype-pretty-code's own
   source) — so `globals.css` gained the two rules that actually turn those
   vars into a visible color, switched by the same `.dark` class
   `use-theme.ts` toggles.

## Adaptations from the plan's literal snippet (code had drifted / had a
stricter existing contract)

- The plan says "`TimelineRow` renders `item.time` as a hover tooltip +
  hourly dividers", but `TimelineRow.tsx` currently has a load-bearing
  contract two existing tests depend on: `TimelineRow({item}).type` must
  equal the dispatched child component directly (e.g. `UsageChip`,
  `ServiceLine` — see `TimelineRow.test.ts`). Wrapping `TimelineRow`'s own
  return value would have broken that. Instead, the tooltip/divider concerns
  were pushed one level up into `Timeline.tsx`'s existing per-row wrapper
  `<div>` (which already exists for virtualizer positioning), leaving
  `TimelineRow.tsx` untouched. This also reads as the better separation of
  concerns: `Timeline.tsx` owns row-wrapper chrome, `TimelineRow.tsx` owns
  kind-dispatch only.
- No `next-themes` dependency was added — the plan's "`next-themes`-style
  toggle" is read as "behaves like next-themes' anti-flash pattern", not "use
  the package". The store is ~50 lines and follows an existing in-repo
  pattern (`document-title-store.ts`) closely enough that pulling in a new
  dependency for one flag felt like the wrong tradeoff.
- The anti-flash script is *not* `dangerouslySetInnerHTML` — this codebase
  has a repeatedly-documented "zero `dangerouslySetInnerHTML` anywhere" rule
  (`lib/markdown.ts`, `lib/unifiedDiff.ts`, `lib/diffHighlight.ts` all cite
  it). A `<script>` tag's plain string children become its literal text
  content in React, which is all an inline script needs — so the rule didn't
  have to bend for this one case either.
