# U4.3 — composer-polish (W4.2b)

Bundle unit. `git log v2-pty-injection..HEAD --oneline` was empty at start —
no prior attempt to reconcile against, built from scratch against
plan-v2.md's Wave 4 §4.2 section (the "Composer:" and "Model selector:"
bullets, plus the "shadcn `Select`"/"pagination" bullets the master TODO
checklist assigns to this unit specifically, even though the prose groups
them under "Shell:" — U4.4 owns the rest of that Shell bullet: toasts,
skeletons, offline banner, PWA icons, decrypted title, archive/delete).

## Sub-tasks landed

1. **Auto-grow composer textarea** — pure CSS: `[field-sizing:content]` +
   `max-h-64` + `overflow-y-auto` on the `<textarea>` in
   `components/timeline/Composer.tsx`. No JS `scrollHeight` measuring effect
   needed, per the plan's own framing.
2. **Draft persistence** — new `features/session-control/composer-draft.ts`
   (`loadDraft`/`saveDraft`/`clearDraft`, `sessionStorage`-backed, keyed
   `falcon:composer-draft:<sessionId>`), following `last-seen.ts`'s exact
   SSR-guard/no-window-safe-no-op pattern. `Composer` now takes a `sessionId`
   prop, lazy-inits `text` from `loadDraft`, saves on every keystroke, clears
   on send and on session switch.
3. **Multi-file attach + image thumbnail previews** — the hidden file input
   gained `multiple`; `handleFileChange` now iterates every selected file,
   calling `onAttach` once per file (the existing per-file attach mutation in
   `use-composer-state.ts` already supported being called more than once — no
   change needed there) and rendering a transient preview chip per file (an
   `<img>` thumbnail via `URL.createObjectURL` for `image/*` files, a
   name/size chip otherwise — gated by the new, unit-tested `isImageFile`
   pure predicate). Previews clear (and revoke their object URLs) once
   `isSending` settles back to `false`.
4. **Crypto-ready gating** — `useComposerState` now also returns
   `cryptoReady` (`cryptoBridge !== null`, the same bridge `sendAttachment`
   already depended on internally) — `Composer`'s attach button is disabled
   whenever it's `false`, with an explanatory `title`. The Send button is
   deliberately *not* gated on this — a text send never touches the crypto
   bridge (see the module doc comment on why).
5. **shadcn `Select` replacements** — new `components/ui/select.tsx` (the
   standard shadcn "new-york" `@radix-ui/react-select` wrapper; added
   `@radix-ui/react-select` to `packages/web/package.json`). Replaced all
   four remaining native `<select>`s: `features/new-session/components/
   options-step.tsx`'s provider/permission-mode/model pickers, and
   `components/timeline/ControlBar.tsx`'s mode selector. Each trigger got an
   explicit `id` + a matching `htmlFor` on its wrapping `<label>` (Radix's
   trigger renders a `<button>`, not a native labelable-by-default `<select>`,
   so biome's `noLabelWithoutControl` needs the explicit association — a
   `<button>` *is* a labelable element per the HTML spec, so this is a
   correct, not just lint-satisfying, fix).
6. **"Load earlier" pagination** — `use-live-render-items.ts` now also
   returns `hasMore`/`isLoadingMore`/`loadEarlier`, passing `useInfiniteQuery`'s
   own `hasNextPage`/`isFetchingNextPage`/`fetchNextPage` straight through
   (the `before`-cursor plumbing already existed in `getSessionMessages`/
   `getNextPageParam` — it just had no caller). `Timeline.tsx` renders a
   plain "Load earlier" button pinned above the virtualized list when
   `hasMore` is true; all three props default to the no-pagination case so
   every existing caller (the timeline demo fixture, tests) is unaffected.
7. **Model selector (spawn)** — new `features/new-session/model-meta.ts`:
   a curated `MODEL_OPTIONS` list per provider (`sonnet`/`opus`/`haiku` for
   Claude Code, `gpt-5.1-codex`/`gpt-5.1-codex-mini` for Codex — short CLI
   aliases, not dated model-id strings, so the list never goes stale) plus a
   "Custom…" escape hatch. `NewSessionForm.model` keeps its existing `""`
   -means-default contract; `OptionsStep` tracks whether the free-text field
   is open as real component state (`customOpen`) rather than trying to
   derive "user picked Custom with a still-blank field" from the model string
   alone — that's genuinely ambiguous with "provider default" once both are
   `""` (documented inline). `DEFAULT_MODEL_VALUE`/`CUSTOM_MODEL_VALUE` are
   non-empty sentinels since Radix's `Select.Item` rejects an empty-string
   `value` outright.
8. **Header model chip** — new `features/session-control/
   use-session-model-chip.ts`: reuses `useSessionCrypto`'s already-unwrapped
   per-session DEK (the same key `bootstrapSession` seals metadata under) to
   open this session's own `metadata` box from the account snapshot and pull
   out an optional `model` field, versioned/reset the same way
   `live-source.ts`'s title decryption and `use-live-render-items.ts`'s
   session-switch reset are. Rendered as a `Badge` next to the session id in
   `SessionTimelineScreen`'s header, only when non-null — a session started
   before the CLI recorded a model shows nothing, not an error.

   This chip needed a real data source to not be permanently-dead code (the
   plan's own phrasing, "once the CLI records it there", flagged this as
   pending), so this unit also made that small, additive CLI-side connection:
   `session/modelFlag.ts` (`extractModelFlag`, a tiny `--model <value>` /
   `--model=value` passthrough-args parser, unit-tested) is now called from
   both `commands/start.ts` and `commands/startCodex.ts` when building the
   session's metadata, and `session/bootstrap.ts`'s `SessionMetadataInput`
   gained an optional `model` field sealed alongside `title`/`path`/
   `providerSessionId`. The `--model` flag itself still reaches the real
   `claude`/`codex` process completely unchanged (full passthrough, per
   `CLAUDE.md`'s CLI skeleton description) — this only *also* reads it for
   the header chip's benefit. `bootstrap.test.ts`'s existing strict
   `toEqual` metadata-shape assertion was updated for the additive `model:
   null` field, plus one new test asserting a given `--model` value round-
   trips into the sealed metadata.

## Adaptations from the plan (drift/judgment calls)

- The plan's prose puts "shadcn `Select`" and "'Load earlier' pagination"
  under the wave doc's "Shell:" bullet, but the master TODO checklist's
  U4.3 entry explicitly lists both as this unit's — followed the checklist
  (the authoritative execution-unit breakdown) over the prose grouping.
- "Header model chip … from session metadata once the CLI records it there"
  was written as a forward-looking, not-yet-wired dependency. Given this
  codebase's explicit "no TODOs" rule and its many documented
  honest-stub-with-injectable-seam precedents (e.g. `providerSessionResolver.ts`),
  wiring the small CLI-side model-into-metadata plumbing felt like the right
  call over shipping a chip that can only ever render `null` — it's fully
  additive (new optional field, new small module) and doesn't touch the
  actual `--model` → process wiring at all.
- Multi-file attach previews clear as a group once every attach call
  launched by one file-selection batch has settled (not per-file, since
  `useComposerState`'s attach mutation doesn't expose per-call-id
  completion) — an accepted, documented simplification rather than adding a
  new tracking mechanism for a purely cosmetic loading indicator.
