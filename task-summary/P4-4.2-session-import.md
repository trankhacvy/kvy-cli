# P4-4.2-session-import — Session import in the New-Session flow

**Section:** 4.2 Adoption Tier 3 + polish
**Type:** (P) port with changes — new web wizard step wired to the already-landed
`adopt.list` wire contract, following `falcon-prd.md` FR-7.8 (UC7 "continue from a
recent CLI session") and `falcon-system-design.md` §4.4's `adopt.list` machine RPC.

## What was implemented

Added a new, optional "Continue session" step to the web New Session wizard
(`packages/web/src/features/new-session/`), between "Directory" and "Options":

- **`types.ts`** — new `ImportCandidate` view-model (mirrors `@falcon/wire`'s
  `ProviderSessionSummary`), a `listImportCandidates(directory)` method added to
  `NewSessionActions`, and an optional `continueFrom` field added to `SpawnRequest`
  (mirrors `SpawnParams.continueFrom` in the wire schema).
- **`wizard-state.ts`** — `WIZARD_STEPS` gained an `"import"` step
  (`machine → directory → import → options → review`); `NewSessionForm` gained
  `importCandidate: ImportCandidate | null` (default `null` — "start fresh"); the
  step is always advanceable (`canAdvance("import", ...)` is always `true` — picking
  a candidate is optional); `buildSpawnRequest` now includes `continueFrom` when a
  candidate was picked.
- **`components/import-step.tsx`** (new) — fetches candidates on mount via
  `actions.listImportCandidates(directory)`, renders "Start a new session" plus one
  card per candidate (title, relative last-activity time, a "Running" badge for
  live processes), loading/error/empty states. Mirrors `MachineStep`'s
  card-as-radio-option pattern and `DirectoryStep`'s browse-on-mount shape.
- **`new-session-screen.tsx`** — wires the new step in, resets `importCandidate` to
  `null` whenever the directory changes (same precedent as the machine step
  resetting `directory` when the machine changes), and the review step now shows
  "Continuing from: <title>" / "Starting fresh".
- **`mock-source.ts`** — seeds `/Users/vy/projects/falcon` with two fake candidates
  (one running, one finished) so the picker and the "no sessions found" empty state
  are both exercisable; every other seeded directory returns `[]`.
- **`live-actions.ts`** — `listImportCandidates` calls the `adopt.list` machine RPC
  (`workspaceId: directory`, same "directory doubles as workspace id" convention
  `spawn` already uses here) and returns `result.items` as-is (the wire shape and
  `ImportCandidate` are structurally identical); `spawn` now forwards
  `request.continueFrom` through to the `spawn` RPC's `continueFrom` param.
- **`index.ts`** — exports `ImportStep` and the `ImportCandidate` type.

### Necessary one-line extension outside `new-session/`

`packages/web/src/sync/machineRpc.ts` (the shared, typed caller-side RPC client
every feature under `features/*` already extends for its own new methods — see its
own doc comment: `adopt.take`/`adopt.mirror` were added there "for
`features/unmanaged-sessions/`") did not yet type `"adopt.list"` as a callable
method, even though `@falcon/wire`'s `AdoptListParamsSchema`/`AdoptListResultSchema`
are already landed. Added `"adopt.list"` to `MachineRpcParams`/`MachineRpcResults`/
`RESULT_SCHEMAS` there, following the exact precedent of the two adjacent `adopt.*`
entries. `@falcon/wire` itself doesn't export `AdoptListParams`/`AdoptListResult`
type aliases (unlike every sibling schema) — rather than touch the wire package,
those two types are derived locally via `z.infer<typeof AdoptListParamsSchema>` /
`z.infer<typeof AdoptListResultSchema>`. Added a matching round-trip unit test in
`packages/web/src/sync/__tests__/machineRpc.test.ts`.

No daemon-side (`packages/cli/src/daemon/machineRpc.ts`) or workspace-registration
changes were made — that file's own doc comment already lists `adopt.list` as a
"separate, later plan bullet" pending the same not-yet-composed workspace registry
seam noted throughout this codebase's `CLAUDE.md`. This task only makes the web
wizard *speak* `adopt.list`'s wire contract; wiring a live daemon handler for it
remains that later task's job, same as every other `features/*` RPC caller in this
codebase today (none are wired to a live `apiSocket` yet either).

## Assumptions

- `adopt.list` candidates carry no `provider` field on the wire (matches
  `ProviderSessionSummarySchema` exactly), so the import step doesn't attempt to
  cross-check/lock the wizard's separately-chosen provider against the picked
  candidate — consistent with Tier-1 adoption currently only indexing Claude Code
  transcripts (falcon-prd.md §5.9).
- Directory continues to double as `workspaceId` for `adopt.list`, matching the
  existing `spawn`/`fs.list` convention in this same file (no workspace registry
  wired in yet).
- Changing the directory after picking an import candidate clears the selection
  (a candidate belongs to the directory it was listed for).
