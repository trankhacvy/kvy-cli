# U4.7 — usage-and-compact (W4.6 — WIRE+CLI+WEB)

plan-v2.md §"W4.6 (C21+C22) Usage + compact markers (wire-additive)". No prior commits

## What landed

1. **Wire (`@falcon/wire`)** — additive `{ t: "usage", inputTokens: number, outputTokens:
   number, costUsd?: number }` member on `SessionEventSchema`'s discriminated union
   (`packages/wire/src/session.ts`). Verified additive-only via the existing
   `additiveOnly.test.ts` (union additions are always backward-compatible — new options
   never fail `isCompatible`).

2. **Mapper emission (`envelopeMapper.ts`, the PTY-injection transcript mapper — this
   branch's real local↔remote bridge, not the ACP path)**:
   - New `pickUsage()` reads an assistant record's real transcript shape
     (`message.message.usage.{input_tokens,output_tokens}` — verified against
     `__fixtures__/0-say-lol-session.jsonl`), returns `undefined` on anything
     missing/malformed so a usage-less line mints no extra envelope.
   - The assistant branch emits one `{t:"usage"}` envelope per record that carries a
     valid `usage`, in the same turn/subagent scope as the content just emitted,
     trailing after the text/tool-start envelopes.
   - Updated the file's own header comment, which previously stated "`SessionEnvelope`
     carries no token-usage field at all ... dropped entirely" — now describes the
     sibling-envelope design instead of leaving a stale/false doc comment in place.

3. **Compact boundary** — the `isCompactSummary` branch (was: silent `return
   envelopes` — plan cited `envelopeMapper.ts:480`, drifted to line ~576 by the time
   this unit ran) now pushes `{t:"service", text:"History compacted (/clear)"}` before
   returning. No turn is opened for it (preserves the pre-existing "`currentTurnId`
   untouched" contract — there was never a turn attached to this line). Renders for
   free through the web's existing `service` → `ServiceLine` path, no new component
   needed for this half.

4. **Adapted beyond the plan's snippet (drift note)**: adding the `usage` variant to
   `SessionEvent` broke an **exhaustive, no-default `switch (ev.t)`** in
   `packages/cli/src/remote/messageBuffer.ts`'s `summarizeEnvelope` (the remote-mode
   terminal's Ink display summarizer) — confirmed by diffing a stashed-vs-restored
   `pnpm --filter falcon build` (fails only with the new wire schema present). Added a
   `case "usage": return null` (the same "nothing useful to show" bar `turn-start` and
   a completed `turn-end` already use — a per-turn token count doesn't belong in the
   terse remote-mode terminal feed; it's a web-only chip) plus a test. Grepped the repo
   for every other place with a matching exhaustive switch (`case "turn-start"`/`"sub-
   stop"` literals) to confirm no other seam was missed: `reduce.ts` and
   `TimelineRow.tsx` (both updated below) were the only other two; `acpToEnvelope.ts`
   only *produces* specific literal events, never exhaustively consumes `SessionEvent`,
   so it needed no change.

5. **Web reducer** (`packages/web/src/sync/reducer/`): new `UsageItem` `RenderItem`
   variant (`types.ts`, exported from `index.ts`), straight-through `case "usage"` in
   `reduce.ts` (mirrors the `service`/`file` cases — no aggregation logic, one
   `RenderItem` per `SessionEnvelope`, consistent with every other event kind here).

6. **Web token chip** — new `packages/web/src/components/timeline/UsageChip.tsx`: a
   quiet, centered chip (same visual register as `ServiceLine`, using the existing
   shadcn `Badge` `outline` variant) showing `↑<input> ↓<output>` token counts, plus
   `· $<costUsd>` when a future adapter ever supplies it (no provider does today — the
   field is wire-reserved only). Wired into `TimelineRow.tsx`'s dispatch switch. New
   `formatTokenCount()` added to the shared `packages/web/src/lib/format.ts` (base-1000
   k/M/B, mirroring `formatBytes`'s existing base-1024 style/tests).
