# U4.4 — shell-polish (W4.2c)

Bundle unit. `git log v2-pty-injection..HEAD --oneline` was empty at start —
no prior attempt to reconcile against, built from scratch against
plan-v2.md's Wave 4 §4.2 "Shell:" bullet (the remainder of W4.2 after U4.2/
U4.3 took the render/composer/pagination/model-selector/shadcn-`Select`
pieces): toasts, skeletons for Home/timeline initial loads, offline/WS
banner, PWA manifest icons, decrypted session title in the timeline header,
and archive/delete wiring.

## Drift from the plan, noted up front

The plan's "Archive/delete: server routes exist (`POST
/v1/sessions/:id/archive`, `DELETE /v1/sessions/:id`) — wire buttons" line
assumed those two routes were already landed; they weren't (checked: no
`archive` route anywhere in `packages/server`, only a comment in
`sessionStatus.ts` deferring it to "later work"). `SessionStatusSchema`
already had `"archived"` in its enum and `UpdateBodySchema` already had both
`session-update{status}` and `session-delete` wire shapes (both unused by
any route) — so the wire contract and the client's `sync/engine.ts` fast-path
were fully ready for this; only the two server routes and their web callers
were missing. Built `packages/server/src/app/routes/sessionArchive.ts`
(`buildSessionArchiveRoutes`) to close that gap: `POST .../archive` mirrors
`sessionStatus.ts`'s "failed" transition shape (idempotent, no CAS — no
legitimate concurrent writer to lose a race against for a user-initiated
archive either); `DELETE /v1/sessions/:id` is a hard row delete (every FK
onto `sessions.id` — `session_messages` — is already `onDelete: "cascade"`
in `schema.ts`). Registered in `server.ts` alongside the other session
routes. No wire-schema changes needed at all (design principle: additive-only
already meant the shapes existed before this task touched anything).

## Sub-tasks landed

1. **Toasts** — added `sonner` as a `@falcon/web` dependency; mounted
   `<Toaster theme={theme} richColors closeButton position="bottom-right" />`
   once in `app/providers.tsx` (the one existing app-chrome wrapper), with
   `theme` following the existing `useTheme()` store so toasts never render
   dark-on-dark/light-on-light. Wired as the feedback channel for the new
   archive/delete mutations (`toast.success`/`toast.error`).

2. **Skeletons** —
   - `components/ui/skeleton.tsx`: the standard shadcn pulsing-block
     primitive.
   - `features/session-list/components/session-list-skeleton.tsx`
     (`SessionListSkeleton`): placeholder workspace-section + `SessionCard`-
     shaped rows. Wired into `SessionListScreen` behind a new
     `SessionListSnapshot.isLoading?: boolean` field (optional — every
     existing fixture/test source that has no async loading phase to model
     just omits it), set from `useSyncSnapshotQuery()`'s own `isLoading` in
     `live-source.ts`. Shown only for the genuine first-load window (nothing
     — session or unmanaged — has rendered yet); a later gap-invalidation
     refetch never re-triggers it.
   - `components/timeline/TimelineSkeleton.tsx`: a handful of message-bubble-
     shaped placeholder rows. Wired into `SessionTimelineScreen` behind a new
     `isInitialLoading: boolean` field on `useLiveRenderItems`'s return
     (`messagesQuery.isLoading` passed straight through, same "additive,
     every existing caller unaffected" shape as the pagination fields U4.3
     already added there).

3. **Offline/WS banner** — `lib/use-connectivity.ts` (`useConnectivity`,
   injectable `ConnectivitySource` seam mirroring `use-session-ephemerals.ts`'s
   `EphemeralSource` precedent) combines `navigator.onLine`
   (`online`/`offline` window events) with `apiSocket`'s own
   `isConnected()`/`connect`/`disconnect` — two independent signals, since a
   reachable network with an unreachable Falcon server only ever shows up in
   the second. `components/OfflineBanner.tsx` renders nothing when both are
   healthy; otherwise a one-line amber banner ("You're offline…" vs.
   "Reconnecting to Falcon…", browser-offline taking priority since nothing
   client-side can fix that one). Mounted once in `providers.tsx`.

4. **PWA manifest icons** — no icon assets existed at all (`public/` had
   only `manifest.webmanifest` + `sw.js`). Designed a small monogram "F"
   icon in the app's own dark-navy/blue palette (`background_color`/
   `theme_color` `#0b0f19`, glyph `#5b9bff` ≈ the dark-theme `--primary` hue)
   as `scripts/icon-source.svg`, rasterized via `rsvg-convert` (available
   locally; the SVG's own header comment documents the regen commands for
   next time) to `public/icon-192.png`, `public/icon-512.png`,
   `public/apple-touch-icon.png` (180×180), plus a hand-packed
   PNG-in-ICO `public/favicon.ico` (16px+32px frames — this format has been
   valid since Vista, no need for a real BMP encoder) and a plain
   `public/icon.svg` copy for the `any`-size manifest entry. Wired into
   `manifest.webmanifest`'s `icons` array and `app/layout.tsx`'s `metadata.icons`
   (`icon`/`apple` link tags) — verified in the exported `out/index.html`
   after `next build`.

5. **Decrypted session title in the header** — `features/session-control/
   use-session-title.ts` (`useSessionTitle`), structurally identical to
   U4.3's `use-session-model-chip.ts` (same DEK via `useSessionCrypto`, same
   `useSyncSnapshotQuery` metadata-version-gated re-decrypt), opening the
   metadata box's `title` field instead of `model`. `SessionTimelineScreen`'s
   header now renders `title ?? sessionId` instead of the literal
   `Session {sessionId}`, and the tab-title override (`useTabAttention`) uses
   the same decrypted title once available.

6. **Archive/delete wiring** — `lib/use-session-lifecycle.ts`
   (`useArchiveSessionMutation`/`useDeleteSessionMutation`): TanStack
   mutations calling the two new `lib/api.ts` client functions
   (`archiveSession`/`deleteSession`), each optimistically patching the
   `['sync']` snapshot cache in `onMutate` (archive: flips `status` in place;
   delete: filters the row out) with rollback + a `toast.error` in `onError`,
   and a `toast.success` on success. The live `session-update`/
   `session-delete` WS fan-out (already fully handled by `sync/engine.ts`,
   unchanged) reconciles moments later to the same state — the optimistic
   patch is a perceived-latency win, not the only path to correctness.
   Two call sites:
   - **Home row** (`features/session-list/components/session-card-actions.tsx`,
     `SessionCardActions`): rendered as a sibling of `SessionCard`'s
     navigating `Link` (not nested inside it — avoids both invalid nested-
     interactive-in-`<a>` HTML and a `stopPropagation` dance), revealed on
     hover/focus. Archive is a direct one-click action (a reversible status
     flip); delete sits behind a shadcn `Dialog` confirm, mirroring
     `ControlBar`'s "End session" precedent from W2.3.
   - **Timeline header** (`components/timeline/SessionHeaderActions.tsx`):
     same two actions, same delete-confirm-dialog shape; both navigate back
     to `/` on success via `next/navigation`'s `useRouter` since there's
     nothing left on this screen worth staying on.
   - Archived sessions deliberately stay visible on Home rather than being
     hidden — confirmed via `status.ts`'s existing (already-landed, unused
     until now) `deriveSessionStatus` branch: `status === "archived"` maps to
     the `"completed"` dot, and `group.ts` has no status-based filtering. Only
     delete is a true "optimistic removal" from the list; archive is an
     in-place status update. This reading was cross-checked against the
     already-built pieces (both existed before this task touched anything)
     rather than assumed.

  ("an archived live session keeps running; W2.3 stop is the 'end it' path")

  offline banner during an actual network drop, icons render correctly on a
  real device's home-screen install) is out of scope for this automated
