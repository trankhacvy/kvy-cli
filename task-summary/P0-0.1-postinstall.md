# P0-0.1-postinstall — Add root postinstall script to build @falcon/wire first

**Section:** Phase 0 — Repo & contracts (M0) / §16 0.1 Scaffold (plan.md §1, §16)
**Port type:** (V) verbatim port, simplified — Happy's `scripts/postinstall.cjs` includes
node_modules patches that don't apply to Falcon (no Prisma/pglite/LiveKit/Pierre/preact
deps in this monorepo); only the "build the shared wire package first" behavior is ported.

## What was done

- **`scripts/postinstall.cjs`** (new) — CommonJS script (matches Happy's `.cjs`
  extension, since root `package.json` is `"type": "module"` and a plain `.js`
  postinstall using `require`/`execSync` would fail to load as CJS otherwise).
  Runs `pnpm --filter @falcon/wire build` via `execSync` with a fixed command
  string (no interpolated input, so no shell-injection surface) and
  `stdio: 'inherit'` so build output/errors are visible during `pnpm install`.
  Supports a `SKIP_FALCON_WIRE_BUILD=1` escape hatch (renamed from Happy's
  `SKIP_HAPPY_WIRE_BUILD`), useful for CI paths that build via `turbo` directly
  and don't want a redundant wire build during install.
- **`package.json`** — added `"postinstall": "node ./scripts/postinstall.cjs"`
  to the root `scripts` block (placed first, mirroring Happy's ordering where
  postinstall is declared near the top of the scripts list).

Not ported from Happy's version: the five `require('../patches/...')` calls
at the top of `postinstall.cjs` — those patch specific node_modules
(`pglite`+`prisma`, `livekit`, `pierre`, `preact`) that are Happy-specific
dependencies not present anywhere in the Falcon dependency tree (`@falcon/wire`
and `@falcon/crypto` only depend on `zod`, `@paralleldrive/cuid2`,
`tweetnacl`, `libsodium-wrappers`). Adding no-op patch requires would be
dead code with no dependency to patch.

## Why this package, why now

`packages/wire` already exists (landed in `P0-0.2-wire-package`) with a
working `build` script (`shx rm -rf dist && tsc --noEmit && pkgroll`) that
produces `dist/index.{cjs,mjs,d.ts}`. Every downstream package (`crypto`,
and later `cli`/`server`/`web`) imports `@falcon/wire` via its published
`exports` map, which points at `./dist/*` — so without a built `dist/`,
those packages fail to resolve the import at typecheck/build/runtime. This
task wires the postinstall hook so `pnpm install` alone (no manual
`pnpm --filter @falcon/wire build` step) leaves the workspace in a buildable
state immediately.

## Assumptions

- `SKIP_FALCON_WIRE_BUILD` is a new env var name (not `SKIP_HAPPY_WIRE_BUILD`)
  since it's namespaced to this project; no existing tooling depends on the
  old name.
- Did not port Happy's node_modules patch-application block — see "Not
  ported" above. If a future Falcon dependency needs a similar patch, it
  should be added as its own `require('../patches/...')` line in this same
  file at that time, following Happy's pattern.
- Left `scripts/postinstall.cjs` un-executable (no `chmod +x`) and invoked via
  `node ./scripts/postinstall.cjs`, matching Happy's own invocation — it's
  never executed directly as a shebang script.
