## One documented, correct deviation from the plan's literal snippet

The plan's `start.ts` snippet opens with `await reportStatusOnce("ended")`
before `ptySession.stop()`. That function/status value **does not exist
anywhere on this branch**: `SessionStatusSchema` (`packages/wire/src/rows.ts`)
is `z.enum(["active", "archived", "failed", "compacted"])` — no `"ended"` — and
the one status-reporting route that exists, `POST /v1/sessions/:id/status`
(`packages/server/src/app/routes/sessionStatus.ts`), hard-codes
`z.literal("failed")` as the only accepted body value. Plan-v2.md itself
attributes the additive `"ended"` transition to **U1.4 "lifecycle-status"**,
which per `plan-v2.md`'s own checklist (and confirmed absent from this
branch's source) has not landed yet. The prior implementer correctly omitted
the call rather than inventing a status value or fabricating a call to a
function that doesn't exist, and left an inline comment explaining exactly why
and what U1.4 will need to wire in. I verified this reasoning against the
actual schema/route source (not just the comment) before accepting it — it's
right. Every other `ControlBar` action already has the same "not gated on
session status" gap today (also documented inline), so this doesn't regress
anything relative to the rest of the file.
