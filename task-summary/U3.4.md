## Scope delivered

### W3.6 — Home screen real status dots + presence

`packages/web/src/features/session-list/live-source.ts`'s `useLiveSessionListSnapshot`
previously hardcoded every session's `items: []` / `attention: null` and derived
`machineOnline` purely from the `lastSeenAt` heuristic. Now:

- **Machine presence**: new `use-machine-presence.ts` (`useMachinePresence` +
  `deriveMachineOnline`) subscribes to the `machine-presence` ephemeral and prefers it
  once one has arrived for a given machine, falling back to the `lastSeenAt` heuristic
  until then (the ephemeral is only emitted on the machine socket's own connect/
  disconnect — server/src/app/socket.ts — so a web client that connects after a machine
  is already online gets no retroactive signal, hence the fallback is load-bearing, not
  cosmetic). Exported from `features/session-list`'s barrel so
  `features/unmanaged-sessions` can share the exact same helper (see below).
- **Items**: `useSessionMessagePages` (`useQueries`, one entry per session id) fetches
  each session's *newest* message page at the real `messagesQueryKey` — deliberately the
  same cache key/shape `features/session-control/use-live-render-items.ts`'s
  `useInfiniteQuery` uses for the Timeline, so `sync/engine.ts`'s per-session
  `message-new` fast-path keeps a Home row's page current, and opening that session's
  Timeline later reuses the same cached page instead of re-fetching. `useDecryptedItems`
  then decrypts + `reduceEnvelopes`'s each session sequentially against one shared
  crypto-bridge worker (mirrors the existing `useDecryptedTitles`'s "one active key at a
  time" reasoning), re-decrypting only sessions whose page's newest `seq` actually moved.
- **Attention**: `useLiveAttention` subscribes to the `attention` ephemeral, fanned
  across every session in the current snapshot (same signal
  `features/session-control/use-session-ephemerals.ts` already consumes per-open-session,
  here multiplexed across every Home row instead).
- `buildSnapshot` (now exported for tests) assembles all of the above into the final
  `SessionListSnapshot`, still degrading honestly (`active` + no items yet → `idle`,
  never a fabricated `working`) exactly as the pre-existing doc comment promised.

**Deviation from the plan's snippet**: plan.md's brief said "TanStack `useQueries`" for
the decrypt step itself; the actual implementation splits this into (1) `useQueries` for
the raw encrypted-page *fetch* (safe against a dynamic session list, and it's what lets
`sync/engine.ts`'s fast-path patch a Home row) and (2) a sequential, single-shared-bridge
decrypt loop in a plain `useEffect` for the *crypto* step — because a crypto-bridge
worker only ever holds one active session key at once (documented in this same file's
`useDecryptedTitles`), so parallel per-session decrypts sharing one bridge would race.
This mirrors `useDecryptedTitles`'s existing pattern rather than inventing a new one.

### W3.10 — Unmanaged sessions → live (read-only)

New `packages/web/src/features/unmanaged-sessions/live-source.ts`
(`useLiveUnmanagedSessions`) reads the same `['sync']` snapshot's `unmanagedSessions` +
`machines`, decrypting each row's `summary` (title/lastActivity/running) and each
referenced machine's name sequentially against one shared bridge (same
one-active-key-at-once pattern as session-list's `useDecryptedTitles`), re-decrypting a
row only when its `updatedAt` has moved (no `.version` on `summary` the way
`metadata`/`agentState` have one). Reuses `useMachinePresence`/`deriveMachineOnline` from
`features/session-list` so a machine shown in both the managed list and this section
agrees on its online state.

`session-list-screen.tsx` now defaults `useUnmanagedSnapshot` to this real hook (was
`useMockUnmanagedSessions`). `useUnmanagedActions` stays mock-backed per the plan's own
scope note ("Actions (mirror/adopt) stay disabled until the adopt RPCs get live wiring")
— but rather than leave a real (non-fixture) session id silently driving a mocked
`adopt.mirror`/`adopt.take` call that only *pretends* to succeed, a new `actionsDisabled`
prop threads from `session-list-screen.tsx` (hardcoded `true` there — it tracks this call
site's actual capability, not something a caller should toggle) through `UnmanagedSection`
→ `UnmanagedSessionCard`, greying out "View" and "Take over" (and skipping mounting
`TakeOverDialog` entirely) instead. Default `actionsDisabled={false}` everywhere else
keeps every other/mock-driven call site (and `app/session/unmanaged/[id]/page.tsx`,
which is unrelated/out of scope here and still runs off its own mock defaults) fully
interactive.
